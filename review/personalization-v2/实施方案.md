# 个性化图谱实施方案（阶段1–4已完成）

日期：2026-10-29。用户已授权执行，阶段1–4已完成并经浏览器验证。实现情况见../个性化前端验收记录.md。以下保留设计约束，后续L1/L2仍不在本次实现范围。

## 1. 范围

本次后续实施保持静态前端、本地JSON和现有D3/SVG引擎；不接真实后端API、LLM或正式学生登录，不增加运行时成绩计算。

教师与学生使用同一公共图谱、同一对象评价快照；角色决定侧栏内容。首个重点对象为DEMO001，同时提供DEMO002/003以验证对象切换和防止状态串用。

40份名册记录与40×3份个人快照用于一致性准备，首版选择器只启用建议齐全的前三名学生，不把其余37人伪装成建议已完整。

## 2. 路径与页面

```text
角色选择
├─ 教师端 → 教师工作台
│  ├─ 班级概览（默认，保留现有功能）
│  └─ 选择学生 → 陈亦航（模拟）· DEMO2024001 → 个人图谱
└─ 学生演示 → 选择模拟姓名与学号 → 我的技能树
```

入口只使用简短的“演示身份”标识，不实现密码、身份验证或正式登录。角色和对象选择是导航上下文，不声称具有真实访问权限控制。

工作台保留角色切换与对象切换。姓名和学号让使用者辨认对象，内部始终使用student_id。默认教师显示班级，默认学生身份DEMO001；三种评价场景继续可切换。

## 3. 视图状态

新增状态：role、subject(type,id)、scenario_id、snapshot_ref、recommendation_bundle_ref；已有的视图模式、缩放、节点固定、选中节点、展开课程和筛选状态继续保留。

- 教师切到某学生，或教师/学生切换到同一学生：保持公共节点位置，替换评价状态和建议。
- 场景切换：整份替换该对象快照，不混合两个场景的值。
- 对象尚未加载完成时，不展示上个对象的分数/建议作为当前结果；用紧凑加载状态。
- 快速切换时使用请求序号或AbortController，只接受最后一次选择的数据，防止慢响应覆盖当前对象。
- 选中节点仍存在时保留选中；对象变化不保留来自上一人的建议。
- 没有相应快照或建议时显示明确空状态，不回退班均或借用其他学生数据。

## 4. 数据迁移方式

不直接在旧公共节点上叠写40个人的status。先新增v2加载器与组合器，再切换应用入口。

```text
manifest → 公共图谱/名册/策略/资源
当前subject + scenario → 评价快照
当前学生 + scenario → 建议包
组合只读展示节点 → 原图谱渲染器 + 角色侧栏
```

班级三个场景迁移成v2快照，保证旧班级分数不变。班级侧栏的通用教师建议在实现时从现有v1内容迁入独立的班级建议映射，或通过旧班级适配层继续展示；不把这些通用建议写回新公共图谱。本轮没有生成班级LLM建议包。

新增DataStore负责按node_id只读关联，并缓存公共图谱、名册、当前对象快照和建议包；manifest、策略和资源清单作为辅助数据加载。切换学生只更换对象快照和建议，切换角色优先复用同一完整建议包再筛选audience。所有版本与对象核对通过后原子替换当前投影；总体建议独立放在overview，逐节点建议以数组挂到sidebar_info。

新增LayoutStore单独保存id、x/y、vx/vy、fx/fy及物理尺寸，不能继续把所有业务字段无差别复制进D3物理节点。现有load()会重跑setupLayout()，因此必须调整初始化和状态读取生命周期，不能宣称D3代码完全不用改。复用原力导向算法，但渲染属性从当前投影读取。

同一graph_ref切学生、角色、场景或建议版本时，不重建simulation、不调用restart、不清空画布、不自动fit，保持节点位置、固定状态和缩放。视口调整、用户拖动、主动重新布局及结构版本变化属于另一类事件，不能承诺所有情况下坐标绝对不动。

由presentation mapper生成fill、stroke_style及提示标记，SVG只读取这些字段。stroke_style不进入公共节点、评价快照或LLM更新包；阶段性低分条件集中在mapper，仍读取预设状态，不计算成绩。选中外环与风险描边分离，避免高亮覆盖风险。

缓存键、投影形状、初始化边界与具体依据见建议评估与数据组合器设计.md。

## 5. 教师个体侧栏

未选节点时：姓名/学号、当前阶段、12项能力画像、优先帮扶节点、依据与建议措施。画像应保留评价覆盖和“暂无评价”，不要只用一个总体平均分概括。

点击节点后：学习状态、学习进度、评价覆盖、个人得分或阶段性掌握度、证据来源、已测薄弱先修、后继学习提醒、教师帮扶措施和复测建议。

只有课程总分时，只指出该课程需要关注，不能凭空定位课程下的薄弱知识点。未学习或未评价的灰色节点不进入薄弱项榜单；阶段性低分单独列为需要关注。

可显示匹配场景的班级参考值，但需明确“个人”与“班级”，先不实现排名、百分位或统计推断。

## 6. 学生侧栏

未选节点时：我的能力画像、当前优势与待提升项、总体学习建议、建议优先完成的少量任务。

点击节点后：我的得分、学习/评价进度、复习步骤、已有证据支持的先修补习项、后继预习提醒和可打开的本地任务单。

同一评价事实不因角色变化而改变。学生侧栏不显示教师帮扶口吻；教师记录未来可影响建议上下文，但不直接原文展示给学生。

## 7. 视觉规则

延续现有布局、三层形状和双模式。不增加大段免责声明或教学实现细节。

- 结构模式保持层级颜色；诊断模式读取当前对象的health_color。
- 灰色+score_is_provisional+score<60继续使用橙红虚线描边，不能简单用红色填充代替“证据不足”。
- 学生值标注“个人得分”，学习中节点标注“已评价部分掌握度”；班级值标“班级平均”；能力值标“达成估计”。
- 完成学习但没有评价、尚未学习、局部评价不足分别保留标签。
- 资源入口显示简短标题，点击打开实际存在的本地材料；无资源则隐藏或显示空状态，不产生死链接。

## 8. 用户审查后的实施顺序

| 阶段 | 实施内容 | 验收结果 |
|---|---|---|
| 1 | DataStore缓存与只读组合、LayoutStore生命周期拆分、presentation mapper、班级兼容适配 | 原班级概览保持可用；同结构切换只更新投影；SVG直接读取stroke_style |
| 2 | 角色入口、教师对象选择、学生模拟身份入口 | DEMO001/002/003可辨认并进入相同个人评价事实 |
| 3 | 教师个人画像与帮扶侧栏、学生画像与复习/资源侧栏 | 总体与每个节点均有对应角色内容 |
| 4 | 三场景联动、进度/证据状态、资源跳转、窄屏与回归 | 不串人、不串角色、坐标稳定，无成绩计算 |

LLM相关工作仍是独立后续阶段，不在上述4阶段自动接入：

| 后续阶段 | 内容 | 要点 |
|---|---|---|
| L1 | 按任务裁剪上下文、提供方/端点输出Schema适配与服务端调用 | 局部一阶/总体摘要分开；先检查响应状态，再做结构和业务校验 |
| L2 | 教师侧栏候选差异预览、确认采纳、原子发布与审计 | active与candidate隔离；采纳时再次校验版本并持久化；学生只读active |

当前DataStore、LayoutStore和个性化界面已实现；L1/L2只保留文档与静态契约，没有实现API适配器、Diff界面或发布服务。

## 9. 验收清单

1. 教师打开班级与DEMO001时标题对象明确，个人分数与班均不混用。
2. 同一学生在教师端与学生端的节点分数、状态、进度一致；文案与行动建议按角色不同。
3. DEMO001→DEMO002→DEMO001可稳定复现各自数据；切换不覆盖任何公共节点源文件。
4. 同对象切换三种场景能区分完整测评、混合证据与仅课程总分。
5. C05学习进度60%与评价覆盖50%分别显示；低分描边规则作用于个人分数。
6. C05.K04可显示学习中且未评价，K05/K06未开始；缺少分数不显示为0分。
7. 仅课程总分时108个知识点均无分数，不生成虚构薄弱定位。
8. 先修/后继提醒有图谱关系依据，建议引用本人的评价证据；资源可打开。
9. 场景/对象快速切换不串数据；缺失数据有空状态，已有缩放、筛选、聚焦和局部展开可回归。
10. 浏览器移动端无横向溢出；没有正式登录、LLM请求或运行时成绩聚合。
11. 同图谱、同视口、模拟稳定后切换对象，节点x/y/fx/fy及缩放不变；快速连续切换时只接受最后一组快照和建议。当前模拟未停止时保持连续运动，不因Join重置。
12. 派生stroke_style覆盖0分、null、未开始、阶段低分、结构/诊断模式；节点选中与hover不覆盖阶段低分描边。

后续LLM阶段另行验收：局部C05上下文仅11个节点，不补造C04→C05；总体画像包含能力覆盖摘要；允许全图存在但本次未提供的节点/证据/资源不得被模型引用；拒绝/截断/空响应不破坏页面；候选取消不改变active，版本过期不能采纳，发布不改节点成绩与坐标。
