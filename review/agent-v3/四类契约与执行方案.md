# 事件驱动诊断 Agent：四类契约与执行方案

2026-10-30。用户已授权连续执行。先确定以下契约，再实现本地服务、模型适配与UI，最后验证和保存Git版本。

## 四类契约

机器Schema在contracts/目录，作者源为agent/contracts.py。schema_version=3.0.0表示新增的运行契约；原v2公共图谱和评价快照保留，不混入运行状态。

| record_type | 主键/绑定 | 作用 |
|---|---|---|
| evaluation_changed | event_id、对象/场景、before/after | 记录已接受的新评价与字段差异、影响节点和请求指纹；重复相同event_id幂等，不同内容复用ID被拒绝 |
| diagnostic_artifact | artifact_id、对象/角色/节点、generated_against、validated_against | 保存解释、证据引用、读节点及查询依赖和语义指纹；publication与validity分开；不改成绩 |
| agent_run | run_id、固定snapshot_ref、触发原因 | 持久化队列、运行/失败/过期状态、有限工具轨迹、用量；恢复时重新排队未完成任务 |
| conversation_turn | turn_id、session_id、对象/角色/节点、固定snapshot_ref | 问题、回答、所讨论解释与回答依据；一轮工具查询始终固定版本，旧回答保留历史标识 |

模型只输出explanation、cited_node_ids、cited_evidence_ids、resource_ids、limitations。模型不能写对象、版本、成绩、状态或关系。解释自动校验保存；正式帮扶方案仍走既有recommendation_update候选协议，本轮不自动采纳教学措施。

## 变化与失效规则

1. 接受完整v2评价快照，校验对象、图谱、策略、证据、数值及权重计算一致性，必须在当前revision上递增。新事实立即可读。
2. 对node_results与相关证据逐字段比较；0/null、学习进度/状态、评价粒度和证据变化均有效。重复事件与仅提交时间变化不触发生成。
3. 计算受影响节点：沿belongs_to/supports向上，先修等只用于解释依赖，不传播分数。总体画像还依赖薄弱/优势排序查询结果。
4. 诊断指纹包括实际读取的节点状态、关系、证据、学习背景、资源与选择查询结果，不包括快照revision和时间戳。相关依赖不同才重新生成。
5. 依赖未变时生成新的重新验证记录，保留原generated_against，更新validated_against；不是篡改旧解释的版本号。
6. 生成完成前再次核对当前快照和指纹。旧任务不覆盖新解释；可复用时必须重新验证依赖，不能静默跨版本。
7. 诊断发布不触发评价事件，避免循环。已有相同对象/角色/节点/版本任务去重；较早队列任务可被新版替代。

## 任务与读取边界

默认局部一阶、总体12项能力与少量重点；最多32节点、32证据、8资源、48000上下文字符。模型最多调用4次（含终答）、6次只读工具，禁止无限查询。若超限、拒绝、空响应、截断或引用不合法，保存失败状态，事实照常展示。

工具提供节点、邻域、评价证据、资源和同对象前版差异读取。工具不接受学生ID或快照参数，作用域由服务端固定；扩大读取只允许初始目标两跳内，并纳入依赖指纹。已读取事实可缓存，不把整个班级或大纲发送给模型。历史对话只取同对象/角色/节点最近少量轮次，旧事实不能覆盖当前快照。

## 实施顺序

1. 写四类JSON Schema与本方案（当前步骤），保留原数据。
2. 新增Python本地服务和SQLite持久化；启动仍为python tools/serve.py。默认只监听127.0.0.1；运行数据库在.runtime/，不纳入Git、不通过静态HTTP提供。
3. 实现完整快照提交、幂等变化事件、诊断队列、依赖检查、过期任务阻断及恢复。浏览器通过轮询读取状态，先不引入消息中间件。
4. 接入可配置OpenAI Chat Completions结构化输出/只读工具适配器。服务器从环境变量或本地.env读取Key/模型；不向浏览器传Key。无配置明确使用rules_demo，不冒充LLM；模型失败不偷偷降级成规则回答。
5. 增加可折叠智能助手抽屉，显示对象/节点/版本、有效诊断和继续追问；右侧节点面板独立展示最新诊断状态。固定评价版本作答，新版出现后标记旧版，下一问默认最新。打开抽屉不改变D3布局。
6. 教师可在DEMO001/C05阶段场景点击“模拟补测”，依次补入预设知识点评价，由程序确定性聚合并产生完整新快照；这只是演示数据入口，不让LLM改分。本轮不做通用原始成绩导入。
7. 单元/HTTP/浏览器验证，再写验收记录并提交Git。

## 发布与范围

自动发布的是诊断解释，非正式复习计划或帮扶措施。追问回答保留在会话中，不自动写回正式建议包。原预置建议依赖旧快照时隐藏并标明，不强行套用新版；后续可按既有候选采纳流程更新。

第一版优先完成个人诊断闭环，面向当前可选3名学生；班级仍是预置总览，个人模拟补测不自动重写班级成绩。外部系统可另行提交相应完整班级评价；不把旧班均伪装成已同步结果。图谱/策略/档案/资源本轮不提供编辑API，但读取时仍校验版本与依赖。

## 验收

- 补测后事实先更新，旧解释立即标旧，新解释异步生成并持久化；重复事件无重复版本。
- 无关节点变化可复用，证据变化或新薄弱项影响相关解释/总体画像；旧任务不可覆盖新版。
- 问题自动绑定对象/节点/评价版本；问答过程中更新评价，旧回答明确标旧且不改新分数。
- 重启保留快照、解释、任务和会话；不串学生/角色，工具越界和非法引用被拒绝。
- 模型适配器以模拟传输验证tool_calls、结构化终答与失败路径。没有Key时只验证规则演示，不宣称真实模型调用成功。
- 原13项前端测试回归，新增后台与浏览器闭环测试；画布位置和缩放不因诊断刷新改变。
